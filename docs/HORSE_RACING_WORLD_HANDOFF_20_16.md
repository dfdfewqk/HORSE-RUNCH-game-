## 구현·수정 완료 (담당 영역)
1. 경주 소유권 고정: NPC-only 경주에서는 시작 당시 말 소유 목장을 race.npcPurseOwners(말 ID → 목장명)에 기록한다. 플레이어 참가 경주도 경제 통합 래퍼에서 완료 당시 NPC 출전마 소유권을 기록한다.
2. 경주 상금 지급: ranch-economy.creditFinishedRaces는 새 경주의 소유권 스냅샷으로 수령 목장을 결정한다. 과거 저장과의 호환성을 위해 스냅샷 없는 레거시 경주는 기존 방식으로 처리한다. npcPurseSettled를 통한 중복 지급 방지는 유지한다.
3. 경매: NPC 자금이 실제 0원일 때 70,000,000원이 있다고 간주하던 두 곳의 fallback을 제거했다. 낙찰 이후 구매자 자금은 실제 잔고에서만 차감된다.
4. 일반 판매: 플레이어가 판매할 때 기존 판매 검증과 명마 기록 처리를 그대로 호출하고 실제 NPC 구매자에게 말을 이전한다. 상대 NPC 자금·마방이 부족하면 판매는 성사되지 않으며 가공 수익을 지급하지 않는다. Economy.buyerForPlayerSale(world,h,price) API가 구매 가능 NPC를 찾는다.
5. 자동 경주 뒤 등록 상태: 경주일 종료 시 실제로 마감된 경기의 미사용 플레이어 등록을 삭제해 향후 훈련·판매·등록을 영구 차단하지 않게 한다. 경기 날짜가 끝나기 전에는 참여 기회를 보존한다.
6. 경주 엔진: 각 시간 단계의 불변 마군 스냅샷으로 근접 주자·추월 여유·마군 방해를 소폭 계산한다. 시간 기준 방향 전환 쿨다운을 둔다. frames[].l과 raceDynamics[] (laneChanges, blockedSeconds)을 **추가**했으며 기존 frames[].p / v, results, behaviorEvents는 유지한다. 교육·궁합이 속도·지구력·파워에 직접 보너스를 주지 않는 원칙을 유지한다.
7. 목장 순위: 최근 경주 점수에 hard cap을 적용하여 장기 플레이 모든 상위 목장이 90점 동점이 되던 현상을 완만한 체감 함수 90*raw/(90+raw)로 교체했다. 최근 360일 기록·과거 소유 목장 귀속·상위 3마리 전력은 보존한다. 정확한 점수 비중은 플레이테스트 밸런스 대상이다.

## 20.17 — 대화로 확정된 NPC 핵심마 보호·경제 생존 규칙 (2026-10-26)

**코드 반영 완료. 별도 브랜치에만 존재하며 main 병합 전.**

- 모든 NPC 목장에 보호 역할을 최대 세 개까지 보존: `racer` 대표 경주마 1마리, `sire` 핵심 씨수말 1마리, `dam` 핵심 번식 암말 1마리. 하나의 말이 경주+번식 역할을 중복 담당할 수 있다.
- 경주 대표마: 현역/나이 2세 이상, 현재 레이팅(없으면 현재 능력), 우승 경력, 최근 360일 G1/G2/G3 기록으로 선정.
- 번식 보호마: 실제 기존 성별(수/암)·3세 이상·미은퇴, `genetic`(없으면 `caps`/기초 스탯), `pedigree`, 기존 부모 ID가 확인되는 실제 자손 성적만 반영. 유전 계산·NPC 교배는 개발하지 않는다.
- `world.ranchEconomy.ranches[ranch.name].coreIds`에 세 역할의 말 ID를 저장. 기존 말이 여전히 적합하면 대표마는 새 경쟁마 점수 7점 이상, 번식마는 5점 이상 초과해야 교체하도록 히스테리시스를 적용. 은퇴·사망·매각으로 대상이 사라지면 다음 적격 말을 자동 선정. 변경은 기존 저장 객체에 필드를 추가하는 방식으로 처리해 저장 키는 그대로 유지한다.
- 핵심마·목장 최저 보유 3마리 보호를 **월말 위기 매각, 일반 NPC 일일 시장, NPC 금요일 특별 경매 출품, 경매 입찰·최종 낙찰, 기존 `buyHorse` 직접 구매** 경로에 적용. 금요일 입찰 후 핵심마로 바뀌면 토요일 정산에서 거래를 거부하고 입찰 금액은 차감하지 않는다.
- 모든 NPC 목장에 3회 연속 경영 위기 후 소액 운영 지원을 명시적 장부 `totalSafetySupport`에 기록. 현재 말이 0마리인 경우에만 최초 실전마(기존 연간 영입 시스템의 `experienced` 비용) 영입이 가능한 최소 재건 자금으로 회복한다. 새 말을 무료 생성하거나 NPC 수를 늘리지 않는다.
- 월말 로그 및 명명 목장 경제 대시보드에 NPC 회생 지원 발생액·누계를 표시.
- **유전·성장·NPC 번식 엔진 미수정.** 채팅 2에서 실제 NPC 교배가 구현되면 현재 자손 성적 추적은 확인된 부모 ID만 기준으로 연동 가능.

## 20.18 — 확정된 주말 경마 기본틀 반영 (2026-10-26)

- 새 \`systems/league-schedule.js\`: **1년 360일·30일/월**이라는 기존 시간 흐름은 건드리지 않고, 게임 전체 7일 주기를 기준으로 토/일 정규 경마일만 생성. 첫해 1일은 월요일로 해석하고 연도 경계에서도 요일을 계속 이어감.
- 가상 경마장 **서림·해온·백운·북령·남풍**을 주말별 순환. 일반 경마일 1곳, G1·G2 주요 경마일은 보조 경마장까지 최대 2곳. 경마장 명칭은 기존 대화에서 유지한 1차안이며 세부 코스 수치는 미확정.
- 확정한 **G3 > G2 > G1의 개최 빈도 방향**을 반영. 기존 G1/G2/일반 경주 상금은 변경하지 않음. 새로운 G1명·대회별 상금·트라이얼·국제 초청전의 정확한 날짜는 미확정으로 코드에 강제하지 않음.
- 안전한 단계적 개편을 위해 경마일 **3경주/일을 임시 유지**. 첫해는 정규 306경주(G1 4·G2 12·G3 61)로 생성. 하루 6~8경주, G1 약 20·G2 약 30·G3 약 64, NPC 목장 48~56곳 및 1,300~1,500마리는 **검증 전 목표**여서 반영하지 않음.
- \`systems/competition-integration.js\`: 새로운 게임과 연도 변경에 주말 일정 연결, 레거시 진행 중 시즌 유지, 새 게임 시작 이전에 만들어진 오프닝 경주 보존, 새로운 일정에 이전 월 24일 G2 덮어쓰기 금지.
- \`index.html\`: 새 모듈 로드 및 \`normalize()\`의 **130경주 초과 레거시 리셋**을 새 일정 저장에는 적용하지 않도록 보호. 기존 저장 키 \`horse_ranch_v193\` 유지.
- 검사: 12년 주말/고유 경주 ID/경마장 최대 2곳/상금 타입/등급 희소성/결정론을 확인하는 \`tests/league_weekends_20_18.test.cjs\` 추가. 별도로 새 시작·오프닝 보존·연도 변경·레거시 시즌 보존 통합 스텁 확인.
- 범위 제외: 확정되지 않은 정확한 G1·G2·G3 연간 횟수, 수득상금 승급 기준, G1 개별 대회 출전권·팬 투표 세부 기준, NPC 말 증원, 시설/은퇴/번식 엔진, 상금 재조정. **구현 완료로 간주하지 말 것.**
- 현재 브라우저 실구동·Windows 및 전체 Node 회귀 테스트는 미검증이며, 경주 증가로 인한 NPC 출전마 부족과 상금 공급 초과를 추가 점검해야 함.
