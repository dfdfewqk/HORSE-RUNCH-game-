## 실제 발견한 문제와 적용
1. **P0 — 손상된 로컬 저장 덮어쓰기:** 구형 `load()`는 JSON 읽기 실패 시 `false`만 반환해 `seed()`가 새 게임으로 덮어썼음. 잘못된 저장을 실제로 넣어 재현함.
   - 새 버전은 마지막 정상 스냅샷을 한 번 백업하고 기본 키를 계속 유지함.
   - 본 저장의 형식/핵심 날짜 필드가 잘못됐으면 백업 복원을 시도함.
   - 둘 다 읽지 못하면 자동 저장을 차단하고 경고를 표시함. 사용자의 명시적인 새 게임 확인 없이는 저장값을 제거하지 않음.
   - 브라우저 저장소 전체 용량 초과 같은 저장 실패도 화면에 경고함.
2. **P1 — 중첩 일괄 진행 상태:** 이전 20.4 일 처리 래퍼는 호출자의 `HR_BATCH_DAY` 플래그를 보존하지 않고 무조건 해제했음. 하루/7일/30일 처리 각각 진입 시 원래 플래그를 보관하고 종료 후 복원하도록 수정함.
3. **P1 — 오래된 저장의 필수 자료 누락:** `log`, `training`, NPC/말 목록의 비정상 요소를 방어적으로 처리하고 유효한 저장의 자금/말 ID/진행 상태는 유지함.
4. **P1 — 새 게임 오작동 위험:** 기존 저장과 백업 제거 전에 확인 대화상자가 나타나도록 수정함.

## 이벤트 연결 순서 (현재 구현을 읽어 확인)
- `advanceDay` 단일 진입점은 기존 확장 스크립트가 순차적으로 래핑함. 공통 로직을 새로 복제하면 이중 처리 위험이 있음.
- 날짜 이동 *전*: 20.4 월말 자동 교육·교육비 결제, NPC 당일 경주 마감(20.12).
- 날짜 이동: 날짜·월·연 변경, 출생 처리, 개별 말 상태·연간 나이 갱신, 등록 경주 자동 진행.
- 날짜 이동 *후*: 연간 노화/세대교체/자연사, 금요일 경매 개장·마감, 월말 기본 사육비 정산, 20.15 시설 교육·지정 기수 조교의 일일 진행.
- 연간 최초 경주 생성은 기존 `generateRaces()`를 사용하므로 이전 연도 경기 상세 열람·장기 전적 UI는 추가 통합 검증이 필요함.

## 다른 채팅 담당에게 필요한 계약
**채팅 2 (말 생애·교육·기수):**
- 하루 진행 외에 별도의 날짜 타이머를 만들지 말 것. 20.15 `schoolAdvance(state,hById)`, `riderAdvance(state,hById,getJockey,getR)`는 기존 진입점에서 호출됨.
- 교육·기수 예약 완료 처리는 동일한 게임 일자에 반복 호출돼도 중복 수료/보상이 없어야 함.
- 저장 필드가 없는 이전 말은 레거시 말로 취급하여 기존 경력과 소유권을 유지할 것.

**채팅 3 (경주·NPC·경제·시장·경매):**
- 기존 `runRace`, `eligible` 래퍼 체인을 유지하고 결과/상금 지급 여부는 경기 ID 기준으로 한 번만 기록할 것.
- NPC 경주는 해당 날짜를 *떠날 때* `closeDay`, 금요일 경매는 *도착 시 개장* 및 다음 날짜로 갈 때 정산하는 기존 규칙을 유지할 것.
- 월말 사육비는 떠나는 달의 `monthKey` 기준으로 한 번만, 교육료 별도 장부와 중복 합산하지 말 것.
- 날짜를 직접 증가시키거나 코어 `advanceDay`를 새로 구현하지 말 것. 인터페이스 변경 요구가 있으면 메인 담당에 전달할 것.
