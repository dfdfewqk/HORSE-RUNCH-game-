## 실재 문제와 수정

1. 기존 `sellHorse`는 일반 말 삭제 후 명마가 아닌 경우 혈통 기록을 남기지 않았다. 새 판매 후크가 `pedigreeArchive`에 동일 ID의 스냅샷을 한 번만 남긴다. **판매는 자연사나 은퇴로 기록하지 않는다**. 태어나지 않은 자마의 부·모가 판매되어 `completeBirths`에서 무한 대기하지 않도록 교배 예약 부모의 일반 판매 및 특별 경매 출품을 막는다.
2. 자연사 혈통 스냅샷에 관찰된 `hrTemperament`가 없어서 해당 조부모가 사망한 뒤에는 유전 형질 조회가 끊겼다. 관찰된 값이 있을 때만 원형 그대로 보존한다. 미기록 형질이나 없는 혈통은 생성하지 않는다. 기존 `pedigreeArchive`와 조상 ID 조회를 계속 사용한다.
3. 기본 날짜 루프의 발굽 감소에는 복구 경로가 없었다. 일상적인 주간 발굽 관리 `routineCare(h,absoluteDay)`를 기존 자동 날짜 진행에 연결한다. 하루 중복 적용과 저장·불러오기 후 재적용을 막는다. 별도 수동 UI는 없다.
4. 20.15의 자동 신체 조교가 성공 여부와 무관하게 체력 부담 없이 진행됐다. 진행 시 피로·컨디션 변화를 반영하고 발굽이 너무 나쁠 때는 자동 조교를 건너뛴다. 신체 피로는 별도의 `hrSchooling.stress`와 섞지 않는다.
5. 위탁 도중 부상 시에도 수업 진도가 증가하던 문제를 수정했다. 부상 중에는 진도를 쌓지 않고 중간 보고를 발행한다. 조기 복귀 시 추가 하루를 허위 지급하지 않으며 기존 습득 숙련도는 유지한다.
6. 30일 선택만으로 모든 말이 반드시 정식 수료하는 문제를 막았다. 최종 관찰 평가는 스트레스·기질과 결합한 **잠정** 기준으로 판정하며 부족하면 부분 수료 처리한다. 교육으로 이미 얻은 기술은 사라지지 않는다. 게이트 안전 판정은 기존의 실제 서로 다른 날짜 2회 검증을 유지한다.

## 새 데이터 / 담당자 연계 계약

- `world.pedigreeArchive[]`: 판매마·자연사마 모두 `id`, `fatherId`, `motherId`, `parents`와 (관찰된 경우) `hrTemperament` 보존. 판매마: `archiveReason='판매'`, `deceased=false`; 자연사마: 기존 자연사 표식 유지.
- `HorseRanchLifeSpan.archivePedigree(world,h,reason,year,owner,achievements)`: 혈통 스냅샷 생성. 동일 ID 중복 금지. 화면 연계는 이 스냅샷을 `pedigreeEntity`와 기존 `allHorseObjects`에서 참조한다.
- `HorseRanchInteraction.routineCare(h,day)`: 절대 게임일(1년=360일)을 받는다. `h.hrRoutineCare.lastHoofCareDay`에 마지막 주간 관리일을 저장한다.
- `h.hrSchooling.courseHistory[].assessmentPassed`와 `returnedEarly`: 수료 평가·조기 복귀 기록. 기존 `result`, `safe` 값은 유지.
- 채팅 1: 위 변경 모듈의 기존 스크립트 로딩 순서·기존 저장 직렬화를 유지하면 별도 `index.html` 인터페이스 변경 불필요. `advanceDay` 실행 시 기존 연결 코드를 통해 반영된다. 공동 파일 수정은 하지 않는다.
- 채팅 3: 신규 경주 스탯 보너스 없음. 기존 `I.raceReaction(h,j,rel,seed)` 사용 유지. 새로 태어난 말은 기존 `hrSchooling.safe` 출전 안전 기준을 계속 사용하며 기존 성마 출전 자격은 소급 제한하지 않는다.
