# HORSE RANCH — NPC 경주마 위탁 계약 (초기 구현)

이 기능은 Chat 1의 초기 목장 운영 수익원으로 도입한 **NPC 소유 경주마 위탁 관리**다.
기존 `horse_ranch_v193` 저장 키, 경주 엔진, NPC 목장 회계, 20.15 교육 엔진을 재작성하지 않는다.
병합 전 Chat 2(말 생애/교육), Chat 3(NPC 경제/경주)와 통합 조율이 필요하다.

## 사용자와 합의한 운영 방향

- 시작 수입원은 **경주 상금 + 외부 경주마 위탁료**로 구분한다.
- 위탁마의 법적/게임상 소유권은 NPC 마주에게 유지된다. 플레이어 보유마 판매·교배·경매 목록에는 들어가지 않는다.
- 기본 사육·컨디션 관리와 일상 성마 조교는 자동화하며, 추가 특별 조교는 사용자가 선택한다.
- 특별 조교 비용은 **NPC 마주가 계약 예산 내 부담**한다.
- **경주 출전 권한을 계약에 넣은 위탁마만** 플레이어가 등록/출전시킬 수 있다.
- 상금은 NPC 마주/플레이어 목장/기수 **80% / 15% / 5%**를 초기 제안값으로 구현한다. 이 비율은 계약 경제 밸런스 논의에 따라 조정할 수 있는 설정값이다.
- 기본 위탁료와 경주 성과 보수는 분리한다.

## 초기 구현 수치 (경제 밸런스 미확정)

| 값 | 초기값 | 의미 |
|---|---:|---|
| 기본 계약 기간 | 30게임 일 | 종료 시 원래 NPC 목장으로 말 반환 |
| 위탁 보수 | 600,000원/계약 | 게임 내 7일마다 분할 지급, 마지막 30일 잔액 |
| 특별 조교 예산 | 300,000원/계약 | NPC가 계약 시 사전 확보하고 미사용액은 종료 시 반환 |
| 기본 사육비 | 5,000원/일 | 한 계약의 30일 총 150,000원, 목장 부담 |
| 일상 신체 조교 | 75,000원/7일 | 여력이 있고 훈련 조건을 만족할 때 진행, 목장 부담 |
| 지정 기수 특별 조교 | 75,000원/7일 | NPC 특별 조교 예산에서 차감 |
| 초반 동시 위탁 | 1마리 | 명성 30 이상 2마리, 80 이상 3마리(추가 조정 가능) |
| 성과 보수 | 80/15/5 | 상금을 마주·목장·기수로 분리, 한 번만 정산 |

**주의:** 위 값은 경제 밸런스에 앞서 실제 동작 검증용으로 둔 초기 설정이다.
보수 60만 원/예산 30만 원/명성 기준/기수 특별 조교 단가 등은 추가 논의에서 확정해야 한다.

## 안전 설계와 시스템 연계

1. 위탁마는 `state.hrConsignment.contracts[].horse`에 별도 보관한다. NPC 목장 보유목록에서 계약 중 잠시 분리되지만 **플레이어의 소유마 목록에 영구 추가하지 않는다**.
2. 신규 계약을 받으려면 NPC가 보유한 말을 2마리 이상 갖고 있어야 한다. 첫 번째 말은 남기며 대표마·번식보호 플래그가 있는 말은 위탁 대상으로 내놓지 않는다.
3. 계약 금액과 조교 예산은 NPC 실제 자금에서 선확보한다. 기간 종료 후 사용되지 않은 조교 예산은 NPC에게 돌아간다.
4. 사육비는 위탁 별도 처리하여 기존 월말 소유마 사육비와 이중 청구하지 않는다. 목장 잔고 부족은 `hrConsignment.unpaidUpkeep`로 남기고 다음 위탁료 수입에서 우선 정산한다.
5. 생애 출생일 기록이 없는 **기존 NPC 성마**는 20.15 새끼말 시설 교육을 직접 실행하지 않고, 기존 `HorseRanchFoalEducation.trainingGain`으로 특별 조교를 수행한다. 출생 기록이 있는 말은 20.15 `HorseRanchInteraction` 시설 교육을 재사용한다.
6. 경기 참가 등록/실행 시에만 원래 `state.horses`에 일시 포함해 정상 경기 API를 이용한다. `finally`에서 제거하고 선택 상태/저장 데이터도 원래대로 복원한다.
7. `allHorseObjects()` 조회는 위탁 중 말까지 포함해 이름/ID 충돌과 혈통 참조를 방지한다.
8. 경주 보수는 완료된 경주의 결과 행에 `consignmentSettlementId`와 분배 기록을 남긴다.
9. 병합 전 게임 소스의 담당별 기능 변경 가능성을 확인한다. `main`은 아직 수정하지 않는다.

## 변경 파일

- `systems/player-consignment.js`: 위탁 계약, 별도 장부, 자동 경과, 특별 조교, 출전 허가, 상금 분배, 관리 UI
- `index.html`: 20.15 다음에 위탁 시스템 스크립트 연결
- `tests/consignment_contract.test.cjs`: 실제 전체 스크립트 순서의 VM 통합 검사

## 테스트 범위

- 신규 게임 오프닝 → 위탁 가능 NPC 말 확인 → 계약 수락 → 마방/소유권 보전
- NPC 위탁비+특별 예산 선차감 → 7일 분할 정산 → 30일 반환 → 미사용 특별 예산 반환
- 계약 중 저장·불러오기, 같은 날 중복 정산 방지
- 일반 위탁의 경주 출전·특별 조교 차단
- NPC 예산 부담의 성마 특별 조교, 중복 예약 차단, 기간 완료
- 경주 출전 권한 계약에 한해 출전 등록/레이스 실행, 상금 80:15:5 분할 및 재정산 차단
- 위탁 계약 도중 30회 하루 진행과 한 번의 30일 진행 최종 상태 일치
- 기존 전체 오프닝 및 5년 게임 스모크 회귀

`tests/full_game_integration.test.cjs` 및 이 테스트는 모의 DOM 기반이다. **실제 Windows Chrome에서 버튼 클릭·화면 배치·장시간 플레이를 직접 확인한 결과는 아니다.**
